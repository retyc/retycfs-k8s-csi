{{ .Chart.Name }} {{ .Chart.Version }} (driver {{ .Values.image.tag | default .Chart.AppVersion }}) is installed as release {{ .Release.Name }} in {{ .Release.Namespace }}.

  kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }}

The controller pods must be 3/3 Running, the node pods 2/2, the enroller 1/1, approved identities or not. A driver
container that is not ready is starting or exiting: see its logs.
Each staged volume runs a mount pod in this namespace, on the node that mounts it:

  kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/name=retycfs-mount -L csi.retycfs.com/pvc,csi.retycfs.com/node

WARNING: the mount pods are privileged (RetycFS, mount propagation). The namespace {{ .Release.Namespace }} must allow it:
  kubectl label namespace {{ .Release.Namespace }} pod-security.kubernetes.io/enforce=privileged
{{- if eq .Release.Namespace "kube-system" }}

WARNING: installed in kube-system. The identities' Secrets (every machine account's keys) live in the release namespace:
whoever reads Secrets in kube-system reads them, and kube-system usually has many such readers. Install the driver in a
namespace of its own (retycfs-system).
{{- end }}

Retyc identities are machine accounts: the enroller requests one per RetycIdentity, and an administrator of the Retyc
organization approves it (Organization > Machines) after checking that its fingerprint is the one shown here:

  kubectl get retycidentity -A
  kubectl -n <namespace> get retycidentity default -o wide

With -o wide, the Approval column is the link to the request. A tenant namespace asks for its own identity, for the tenant classes,
with this RetycIdentity (kubectl -n <namespace> apply -f):

  apiVersion: csi.retycfs.com/v1alpha1
  kind: RetycIdentity
  metadata:
    name: default
  {{- if not .Values.identity.organizationID }}
  spec:
    organizationID: <Retyc organization UUID>
  {{- end }}
{{- if .Values.identity.organizationID }}

Cluster-wide identity: RetycIdentity "default" of {{ .Release.Namespace }} (organization {{ .Values.identity.organizationID }}), created
by the enroller, Secret "{{ include "retycfs-csi.identitySecretName" . }}". The pods are ready without it; the claims of the
cluster-wide classes stay Pending until it is approved:

  kubectl -n {{ .Release.Namespace }} get retycidentity default -o wide

Deleting it enrolls a new machine (a new request to approve); the old one stays in Retyc until disabled there.
Changing identity.organizationID later does not move it: delete it to enroll in the new organization.
{{- else }}

No cluster-wide identity (identity.organizationID is empty): the StorageClasses without tenant: true are not installed,
and only the tenants' identities are served.
{{- end }}

A ReadWriteMany claim on one of them is a Retyc dataroom shared by every pod that mounts it. The claim needs the
csi.retycfs.com/uid annotation: every file belongs to that UID, and only pods running as it can write.
{{- if and .Values.admissionPolicy.enabled $classes }}
The ValidatingAdmissionPolicy {{ include "retycfs-csi.fullname" . }}-pvc-annotations checks the csi.retycfs.com/* annotations.
For a StatefulSet, put csi.retycfs.com/uid in its volumeClaimTemplates: otherwise every claim it creates is refused, and
the StatefulSet controller retries in a loop.
{{- end }}
